All resources live inside a dedicated VPC with public subnets (ALB, NAT
gateway) and private subnets (ECS tasks, RDS, EFS mount targets) — the
database, shared filesystem and application containers are never directly
reachable from the internet.

## Modules

| Module | Responsibility |
|---|---|
| `network` | VPC, public/private subnets, NAT gateway, routing |
| `alb` | Application Load Balancer, target group, security group |
| `ecs` | Fargate cluster, Moodle task/service, scheduled cron task, IAM roles |
| `ecr` | Container registry with image scanning + lifecycle policy |
| `rds` | MySQL instance, Secrets Manager credentials, security group |
| `efs` | Shared filesystem for `moodledata/`, mount targets, access point |
| `monitoring` | CloudWatch alarms, dashboard, SNS topic |
| `cdn` | Optional CloudFront distribution in front of the ALB |
| `dns` | Optional Route53 records for a custom domain |
| `waf` | Reusable WAFv2 Web ACL (managed rules + rate limit) — one instance protects the ALB, another (when CDN is on) protects CloudFront |
| `tags` | Single source of truth for the standard tag set (FinOps) |

Each is wired together per environment in
[`terraform/environments/app/main.tf`](../terraform/environments/app/main.tf).

## Why these design decisions

- **Modular Terraform, not one big file.** Each concern is its own
  reusable module with explicit inputs/outputs. This mirrors how I've
  structured Terraform on real client engagements — see the note on
  origin in the main [README](../README.md).
- **No secrets in the container image or in `config.php`.** Database
  credentials are generated by Terraform (`random_password`), stored in
  Secrets Manager, and injected into the ECS task at runtime via the task
  definition's `secrets` block.
- **Cron as its own scheduled task, not a sidecar loop.** Moodle needs
  `admin/cli/cron.php` to run every minute. Baking a `while true; sleep
  60` loop into the main container mixes two lifecycles in one process;
  an EventBridge-triggered Fargate task keeps them independent and lets
  each scale/fail on its own.
- **EFS instead of local task storage.** With more than one ECS task
  behind the same load balancer, a file uploaded to task A must be
  visible to task B. EFS, mounted via an IAM-authenticated access point
  scoped to `/moodledata`, is what makes `desired_count > 1` safe rather
  than just "usually works."
- **One NAT gateway per AZ by default.** A NAT/AZ outage then only
  takes down outbound internet for that AZ's private subnets, not the
  whole environment — high availability is a Well-Architected/SRE
  pillar, not an optional extra. `single_nat_gateway = true` is
  available as an explicit, named cost trade-off for dev/staging.
- **HTTPS and WAF are both opt-in, same reasoning as CDN/DNS below.**
  The ALB gets an HTTPS listener the moment `acm_certificate_arn` is
  set (redirecting HTTP to it automatically), and `enable_waf` attaches
  a WAFv2 Web ACL (AWS managed rule groups + a per-IP rate limit) to
  the ALB, and to CloudFront too when `enable_cdn` is also on. Neither
  needs new code to turn on later — only a certificate and a variable.
- **CDN and DNS are both opt-in.** A CloudFront distribution and a
  Route53 record only pay for themselves once there's real traffic
  outside a single region and a domain to point at it. Dev runs without
  either; staging/prod turn them on via `enable_cdn` / `domain_name` in
  their own `.tfvars`.
- **One codebase, three `.tfvars` files, Terraform workspaces.**
  dev/staging/prod never fork the code — only `db_instance_class`,
  `db_multi_az`, `desired_count`, `enable_cdn` and `alarm_email` differ.
  See [deployment-guide.md](deployment-guide.md).
- **A dedicated tags module.** Every resource carries the same
  `Project`/`Environment`/`ManagedBy`/`CostCenter`/`Owner` keys from one
  place, which is what makes AWS Cost Explorer usable for this project
  instead of a wall of untagged line items.
- **Immutable image tags + vulnerability scanning before push.** The ECR
  repository is `IMMUTABLE`, and the build pipeline fails on
  HIGH/CRITICAL CVEs via Trivy before an image is ever pushed.
- **`apply` requires a manual trigger**, gated behind a GitHub
  Environment approval. `plan` runs automatically on every pull request
  so the diff is visible in review.
- **A dedicated security group per tier** (ALB, ECS service, RDS, EFS),
  each only allowing the minimum inbound traffic from the tier in front
  of it.
